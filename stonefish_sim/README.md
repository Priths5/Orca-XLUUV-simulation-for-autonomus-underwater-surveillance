# Orca XLUUV Stonefish scenarios

Standalone simulators built on [Stonefish](https://github.com/patrykcieslak/stonefish)
(tested with Stonefish 1.6 installed in `/usr/local`). Stonefish must already be
built and installed (`find_package(Stonefish REQUIRED)`); this project does not
vendor it.

| Executable          | Scenario file                       | What it does |
|---------------------|-------------------------------------|--------------|
| `orca_sim`          | `resources/orca_world.scn`          | Original: a single Orca floating in open ocean (no mission logic). |
| `orca_survey_sim`   | `resources/orca_survey_world.scn`   | Scenario 1: lawnmower seabed survey, reactive avoidance of rocks, pillars, wrecks, boulders and fish schools (C++ autopilot). |
| `orca_multisub_sim` | `resources/orca_multisub_world.scn` | Scenario 2: survey while two other survey subs cross the lanes (C++ autopilot on all three). |
| **`orca_rl_sim`**   | any of the above, plus **`resources/orca_rl_world.scn`** | **ROS 2-aware executable: the Orca is driven by the Python RL policy over ROS 2** (or by the original autopilot with `--mode autopilot`). Built only when ROS 2 is sourced. |
| `orca_rl_adapter_test` | -                                | Unit test of the RL command -> thruster force conversion. |

## Build

```bash
source /opt/ros/jazzy/setup.bash     # optional: without it orca_rl_sim is skipped
mkdir -p build && cd build
cmake ..
make -j$(nproc)
./orca_rl_adapter_test
```

Run from `build/` so `./resources/` resolves (`orca_rl_sim` finds `resources/`
next to its own binary, from any directory):

```bash
./orca_survey_sim
./orca_multisub_sim
./orca_rl_sim --world rl                    # waits for RL commands on /orca/cmd/setpoint
./orca_rl_sim --world survey --mode autopilot
./orca_rl_sim --world multisub --headless --rtf 3
```

`orca_rl_sim` options: `--world rl|survey|multisub`, `--mode rl|autopilot`,
`--headless` (Stonefish ConsoleSimulationApp, no window), `--rtf <factor>`
(simulation speed vs real time), `--data <dir>`, then `--ros-args ...`.
ROS 2 interface, frames and the RL side are documented in `../README.md`.

## orca_rl_world.scn - the base world with obstacles

Generated by `tools/make_rl_world.py` (edit that, re-run, rebuild). Open ocean,
30 m flat seabed, and things the Orca must detect with its own sonar while it
scouts a 160 x 120 m area at 12 m depth:

* 12 rock pinnacles and 2 ridge walls rising from the seabed to 4 m depth,
* 2 large boulders between the survey lanes,
* 3 fish schools (9 collidable animated fish, ~2 m/s loops) crossing the lanes,
* `TrafficSub`, an independent survey submarine flying north-south legs across
  the Orca's east-west lanes with its own `OrcaController` (autopilot +
  reactive avoidance).

`resources/orca_rl_world_obstacles.json` lists the same obstacles for plotting
and evaluation only - nothing feeds it to the policy.

## Fixes to the original model files (found while integrating)

All three were verified in Stonefish before/after:

1. **The Orca and the survey subs capsized.** Stonefish's own mass properties
   (probe in `../README.md`) showed the CG 0.05 m *above* the CB on the Orca
   (solid Composite sail) and 0.06 m above plus 0.2 m aft on the survey sub,
   which was also 237 kg heavy. In every scenario the hull pitched up and rolled
   past 170 deg within ~35 s (vijay's survey demo included); the sub sank to the
   seabed. Fix: sail/mast (and sub fins) made of `SyntacticFoam`
   (500 kg/m3, added to every world's `<materials>`), with the removed mass
   carried as an internal `KeelBallast` placed so CG and CB line up fore-aft.
   Result: same net buoyancy (Orca +42 kg, sub +5 kg), CG 0.084 m / 0.128 m below
   CB. The survey autopilot now completes its lanes with roll ~0 deg and pitch
   <= 10 deg.
2. **The DVL never had bottom lock.** `<range velocity="15.0"/>` leaves
   `altitude_max` at Stonefish's ~1e30 default; the DVL ray-march then runs
   `ceil(1e30)` -> 0 steps. Added `altitude_min="0.5" altitude_max="100.0"`.
   Altitude/velocity now arrive (e.g. 16.0 m in `orca_rl_world`).
3. **Multibeam coverage stopped after the first fan.** `ScalarSensor::getLastSample()`
   returns a copy whose `getId()` is always 0, so `OrcaController::AccumulateMultibeam`
   accepted only one sample. It now de-duplicates by sample timestamp
   (coverage grows normally, e.g. 5 -> 144 cells in the same 235 s run).

Other build changes: resources are copied by an always-run `copy_resources`
target (edited `.scn` files reach `build/` even when nothing relinks), and the
RL target is optional so the demos still build without ROS 2.

## How the original scenarios work (unchanged)

* `orca_survey_world.scn` scatters rocks, pillars, wrecks, boulders across a sand
  seabed at 18 m and loops fish schools on spline trajectories.
* `data/orca_xluuv_survey.scn` carries a forward **Profiler** (single swept beam,
  160 deg, 64 steps, 10 Hz, 30 m: obstacle detection) and a downward **Multibeam**
  (survey), plus IMU / DVL / GPS / Pressure / Odometry, and MainThruster
  (`simple_thruster`), YawThruster and HeaveThruster (`push`).
* `OrcaController` flies a lawnmower; when the Profiler's latest sweep shows
  something inside the safety distance it cuts thrust and steers away. With
  `SetAutopilot(false)` it applies externally supplied forces instead - that is
  the hook `orca_rl_sim` uses for RL control.
* `Odometry` is a ground-truth-style sensor. The autopilot uses it; the RL side
  uses it only in the explicit `DEBUG_GROUND_TRUTH` mode.
